The four open questions — answered where the build permits

1. Templating — how does a customer's own EBR structure get in, and does the system feed back into it?
Named, not built. The import branch exists at onboarding A. No feedback mechanism exists for a structure change mid-relationship propagating anywhere — not even named as a future stage yet.
2. What defines "good" — a baseline standard, or invented per-client?
The build already answers this without anyone deciding it on purpose: Baseline Read compares against a peer cohort (same tier + industry), not an absolute standard — cohort-relative, chosen once at onboarding, never revisited per finding. D as built.
3. Co-authoring — is Accept/Edit/Dispute real threading, or one-directional?
One-directional, confirmed. Real threading needs at minimum: a Jordan-side queue, a resolution action he can take, and a way for Priya to see what he resolved and why — three missing screens, not a small patch.
4. The logistical magic — does it have a backstage process now?
Named more precisely, not solved. Reconciliation has vocabulary + authored reasoning but no engine. Cross-tenant benchmarking has a named-but-unauthorized cohort. History extraction has zero parser. API normalization across the 7 sources has never been named at all — this build can't even point to a stub.
