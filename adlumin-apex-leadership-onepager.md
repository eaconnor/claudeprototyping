# Bringing Adlumin onto Apex

**For:** Adlumin Engineering & Product leadership
**From:** Apex Design (Elizabeth Connor, Apex Manager · Luke Kelly, Apex Lead)
**Date:** June 2026
**Status:** Proposal — activation decision

---

## The short version

Adlumin's Apex foundation is **already built.** The brand-specific token layer (`bridge-adlumin.css`) exists today; the shadow-component library is shared and unchanged across products. What's left is a decision to **activate**, not a project to construct.

We're asking for that decision now. We'll bring the hard efficiency metrics behind it as we go — and we're naming, up front, the numbers we don't yet have.

---

## Why this is worth doing

**One design system, every surface.** Apex delivers design decisions through a token pipeline — Figma → semantic tokens → framework-agnostic web components. It works on legacy and modern stacks alike, with no framework migration and no rewrite.

**What Adlumin gets on activation:**

- **Dark mode + accessibility modes** (high-visibility, color-blind palettes) — a runtime toggle, not a sprint.
- **Brand and theme changes in minutes, not weeks.** A token file change propagates everywhere at once. Brand work that historically took 4–8 weeks of engineering collapses to a single file.
- **Free inheritance.** Every shared component built for any product — N-central, N-sight, Cove, Fusion — becomes Adlumin's component automatically, already brand-correct and dark-mode-correct.
- **Additive and reversible.** Components mount alongside existing UI behind feature flags. Nothing in the core codebase has to change; rollback is a flag toggle.
- **A path to Figma Code Connect** (near-term, on the roadmap): design hands off correct, copy-pasteable component code with zero translation loss.

---

## What we can prove today

These are verified against real Figma and repository data:

- All five core products — including Adlumin — already use Apex at the product level.
- **99.95%** Figma library adoption across the design system (8,164 component insertions, 4 detachments).
- **93.75%** of the Apex component catalog is in active use.
- Adlumin's brand token layer is already authored and ready.

---

## What we'll measure next (the honest gap)

We are **not** going to hand you a fabricated efficiency number. Engineering-hours-saved and development-speed gains are real in principle but **we do not yet have an Adlumin baseline** — and we'd rather say so than quote a figure we can't defend.

Our commitment: as part of activation, we will instrument and report back on —

1. **Engineering time per UI feature** — before vs. after, on Adlumin's own work.
2. **Brand/theme change turnaround** — measured, not estimated.
3. **Component reuse rate** in Adlumin's codebase.
4. **Designer and developer satisfaction** — via survey, role-split.

You'll get the dashboard. We're asking you to fund the activation *and* the measurement together, so the ROI is grounded in Adlumin's reality rather than borrowed from someone else's.

---

## The ask

Approve activation of Apex for Adlumin. The foundation is built; the cost is integration effort, not construction. We'll return with Adlumin-specific metrics on the cadence above.
