Branch A · Package 5 · Client-Facing Proof, Cross-Vendor

A QBR coworker that tells one story across every vendor in the stack

Tier 0 — Concept

Most MSPs run 6–8 competing tools per client and can't tell a single comparable story from them. This asks what it would take — legally and technically — for an AI coworker to normalize the whole mixed-vendor stack into one client-ready quarterly narrative.

The problem

An MSP can't prove its value in one narrative because the evidence lives in 6+ vendor tools that don't talk to each other. The most convincing comparison — across the whole stack, not just N-able's slice — is also the one hardest to legally assemble.

The value prop

For MSPs who assemble quarterly reviews by hand: a client-ready, evidence-tagged narrative across the full vendor stack in under 20 minutes — one normalized story with defensibility built in, not another single-vendor dashboard.

Why now

#1 requested capability across all three Guidepoint research instruments — MSPs call it "the holy grail." No incumbent ships it. But demand has only been tested for the destination (a cross-stack QBR), never the mechanism (AI drafts, human edits).

Branch B · Package 3 · Client-Facing Proof, N-able Native

The same QBR, scoped to what's already buildable

Tier 0 — Concept

Same wicked problem as Branch A — client-ready proof of protection — but scoped to MSPs consolidated on N-central + Cove + Adlumin. No normalization dependency, no competitor ToS risk, "Measured" claims defensible on day one.

The problem

MSPs author every QBR by hand — 2 to 4 hours per client, no consistent evidence framework. Even scoped to one stack, the MSP still has to decide what to say — the last mile of proof-of-value has never been automated.

The value prop

For N-able-stack MSPs: a client-ready, defensibility-tagged quarterly review from first-party telemetry in under 20 minutes. No normalization needed — but limited to clients on an N-able stack.

Why now

The plumbing already exists: Runbook Engine (49/49 built) and Value Ledger (52/52 built, renders $0 today). This is a runbook wired to existing infrastructure, not a new platform or a new data acquisition.

Package 4 · Live IR/RCA Security Package

The root cause, written during the incident — not days after it

Tier 0 — Concept

When something gets through, a coworker builds the customer-ready root-cause report as the incident unfolds — cross-stack, confidence-tagged, defensible by morning. Tests whether a live RCA is trusted enough to send to a client and an insurer without a human rewrite, and whether the data to build it is even reachable.

The problem

Post-incident, MSPs reconstruct what happened by hand, days later, from fragmented logs across six tools and three threads. The report is a liability artifact — a wrong root cause narrated confidently destroys credibility in one sentence.

The wedge — during, not after

"Doing the RCA during the incident is equivalent to helping resolve it."— MSP, source interview

Post-hoc, the same report collapses into a smaller, commoditizable text-synthesizer. During, it's part of the response — that's why a client pays.

Why now

This is the #1 named driver on cyber-insurance policies — compliance-driven willingness to pay is real, not assumed. The gap is that a defensible version of the proof only exists days later, if at all.

Package 1 · vCIO/vCISO Advisory Package

Not a coworker — a way to sell what the coworkers already prove

Tier 0 — Concept

A positioning and billing layer that bundles proof coworkers — QBR + Environment Health + roadmap/planning as "vCIO," IR RCA + Tabletop + Alert Flood + identity as "vCISO" — into a flat-fee advisory retainer, priced by MSP practice size instead of per tool. Highest naive survival of any package in the portfolio, and it depends on Branch A/B existing underneath it first.

The problem

MSPs want to expand from break-fix into advisory, but have no scalable proof layer and no billing mechanism for practice-based pricing. Today N-able's tooling is priced and packaged as tools, full stop.

The lever — flat fee, not revenue share

~14% naive survival flat-fee vs. ~0.02% revenue-share — a 700× swing on one pricing decision.

No channel precedent exists for revenue-share, and the billing infrastructure for practice-based pricing doesn't exist in any N-able system today.

Why now

vCISO/vCIO is the highest-value use case named in Guidepoint. Vendor-sponsored research (n=200) says MSPs offering vCISO tripled 21%→67% YoY, 81% already using AI/automation. [CS: MEDIUM — WOBBLY, vendor-sponsored]
