What this tests

Whether making EBR prep — the PICKING sequence, the four cycle-memory SHORTs, per-part staleness — visible as structured, honest UI changes how a technical practitioner (Marcus) and account manager (Vanessa) experience cycle 2+ prep, versus the current all-manual, no-cycle-memory workflow. Built on CS: MEDIUM n=1 primary research from one MSP, fictionalized here as Holt / Marcus / Vanessa. This is directional, not validated.

What you nailed

  • Problem sourced to direct interview quotes with timestamps, not paraphrase (SRC-U-009, 38:01 / 46:59–47:54).
  • Stage 5 shows Marcus frontstage and backstage — the old prototype's prep-only treatment is corrected.
  • "Cannot tell" built as a real, selectable, non-defaulted UI state, not collapsed into a status pill.
  • The four SHORTs get one consistent Ask→Learn→Automate/Kit ladder, plus a distinct Draft status — the notebook's non-existence is a concrete visual pattern, not aspirational copy.
  • Tool-stack conflicts resolved before build: correct vendor names confirmed (uSecure, HaloPSA, N-central, Inforcer, Cloud Capsule) and the correct risk framework confirmed (NCSC 10 Steps + Cyber Essentials).

What will hurt you

  • GOOD FOR staleness windows are authored, not measured — a wrong window trains false confidence silently. UI marks them "est." but the numbers underneath are still guesses.
  • The three headline stats (3h / 1.5–2h / 80%→50%) are unverified against the source recording — shown here CS: MEDIUM, not as confident numbers.
  • All 28 KIT parts source from vendors Harness doesn't own (N-central, Inforcer, HaloPSA, uSecure, Cloud Capsule). The one differentiator — the notebook — is the one thing not built.
  • Vanessa's tabs have visual parity in this build, not functional parity — Forward Intelligence and Referrals still have zero tool path.
  • n=1: one MSP, one owner, one practitioner. Hi-fi polish risks a test participant from a different MSP reading Technica-specific structure as sector-standard.
  • Nobody is named accountable for building the notebook (Structure = unknown, Gate 2). This can test well and still have no owner to build it.
