This is a working walkthrough of the EBR cycle from inside Bracken, not a connected product. It tests whether "Marcus's screen" and "Priya's screen" are different enough to be worth building separately — not whether the underlying grading is accurate.

What's real vs. fabricated

  • Real: the pull (actual HTTP, actual latency, actual byte counts), the reconciliation (three spellings of one server genuinely collapse), the role switch, the gating — sign-off really blocks delivery, sub-0.80 findings are really excluded.
  • Rigged: the join works because the fixtures were authored to join. Real MSP data has assets living in one system under a name no normalizer recovers.
  • Fabricated: every grade, every confidence score, every gap→consequence leap. No model runs. 0.72 is a number I chose.

What you nailed

  • The Unverified hard-block is enforced, not just described — try including finding #4 without verifying it first.
  • Marcus and Priya genuinely see different screens at the same step, sourced directly from the blueprint's own Frontstage/Backstage rows.

What will hurt you

  • The finding set is fixed and fictional — swapping in real Bracken/Fenwick data would need the six MCP connectors the blueprint already flagged as unbuilt.
  • Only one person can drive at a time. If you actually want two people live at once, this needs real state sync — a bigger build than this.
  • Nobody has named the real sign-off owner (Marcus or Priya) — this simulator lets whichever role is active sign off, which papers over an open decision.
