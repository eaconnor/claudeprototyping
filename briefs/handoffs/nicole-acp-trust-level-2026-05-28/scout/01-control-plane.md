## Key Concepts for Trust-Level Model Prototype

### Trust Model & Earned Autonomy
The ACP addresses trustworthiness when MSPs first use AI Agents and Coworkers.

From Ewan Cameron's experiment:
> "We believe that… the concept of L4 earned autonomy — where an AI Expert co-worker graduates from 'human confirms' to 'AI executes, human audits' — can be represented as a coherent, self-evident UX concept that a mature MSP would immediately understand without explanation."

AI Experts and AI Coworkers are assigned trust-execution levels based on track record.

### Value Ledger (Five Monetization Layers)
Each AI Coworker has a **Value Score**:
- Estimated time to complete task manually
- Time to complete with AI Coworker
- Tracks time saved per action
- Aggregate value per coworker
- Cumulative value over time

Makes AI value visible, measurable, and defensible.

### Trust-Level Calculation Components
The trust score combines:
1. **Track record** — success rate over time
2. **Risk classification** — what can go wrong
3. **Scope boundaries** — what the agent can/cannot do
4. **Escalation rules** — when human approval is required
5. **Audit trail** — every action logged with timestamp

### Monetization Context
Five revenue layers (stack together):
1. Platform Access (Subscription)
2. Workflow Execution (Consumption)
3. Expert Licensing (Catalogue)
4. Vendor Ecosystem (Marketplace)
5. MCP & Tool Transactions (Metered)

Layer 3 (Expert Licensing) is where trust-level becomes monetizable — MSPs pay recurring fees for each Expert, and trust level determines how much labor each Expert replaces.
