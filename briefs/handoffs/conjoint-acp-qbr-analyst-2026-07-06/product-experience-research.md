# ▶ TL;DR — read this first (60 seconds)

**What the research points to is NOT "build the screen" yet.** It's: *two cheap research steps (≈ one parallel week) that resolve the load-bearing unknowns before any build.*

**What the evidence says:** The problem is real and the white space is real. What we can't yet confirm is whether it's **buildable at full scope** and **ownable economically as a standalone**. The market signal points toward building it as **part of the N-able platform, not a standalone product**.

- ✅ **Wanted** — QBR Analyst is the #1-ranked, build-first coworker in Nicole's 8-interview study (total 31, #1 three times). [R]
- ✅ **Unoccupied** — *nobody* does true cross-vendor end-to-end QBR normalization (two independent absence-findings). Backup Radar proves the mechanic works for one data type. [CS: MEDIUM]
- ✅ **Growing market** — managed services ~$309–460B / ~9–14% CAGR; the real wave is agentic-AI-in-channel (Canalys: $15B→$158B, 59% CAGR). [D, WOBBLY]
- ⚠️ **Money signal is a warning** — funding is landing on *adjacent* jobs (Rewst $76M automation, Cynomi $37M vCISO, BrightGauge→ConnectWise). No one has won on QBR-as-product. Market votes *feature-of-platform*, not standalone.
- ⚠️ **Buyer wants consolidation** — ~two-thirds want *fewer* vendors. Cuts against a new point tool; favors platform-embedded.

### 🔀 Three shapes a successful concept could take
The evidence doesn't force one design — it leaves three viable configurations. **Gate A + B don't just de-risk; they select among these.**
- **A · Platform-embedded** *(market signal favors this)* — QBR as a capability inside the N-able stack; bundled / retention-defense pricing; leans on latent Doblin types (Product System, Channel, Service). Bets that consolidation + RMM-cannibalization make a standalone unwinnable. **Lowest WTP risk.**
- **B · Standalone cross-stack product** — priced on value, sold beyond N-able's base. **Highest moat + reward, highest risk** (WTP vs. free-in-RMM; full normalization must work). The venture money isn't here yet.
- **C · Narrow N-able-stack QBR** *(the Gate-A "NARROW" fallback)* — drop the cross-stack promise; ship the review over N-able's own stack (N-central + Cove). **Fastest, lowest feasibility risk, smallest differentiation** — a beachhead, not the moat.

### ⬛ MUSTS FOR MVP — what the thin slice must DO (once gates clear)
The MVP is the **trust wedge**: the thinnest thing that earns *"I'd send this with <15 min editing, and I can explain every number."*
| # | The MVP must… | Ties to riskiest assumption |
|---|---|---|
| **V1** | Do a **real Enter** — connect one design-partner's *actual* tools (do not fake the connection) | #1 (riskiest) |

| **V3** | Make every number's provenance **drillable**, not decorative | #3 |
| **V4** | Surface the gap **backstage** (MSP-only), never in the client export | #6 |

**MVP success bar (the KR):** 70%+ of test partners would send with <15 min editing AND can trace every number to source.
**Explicitly OUT of MVP:** scheduled delivery · portal publish · CRM pipeline · full 6–8 integration set · quarter-over-quarter memory · all audience modes · section management · forward-looking slate.

# (i) BUILD VS BUY + THE IRREPLACEABLE CORE

Pattern: **the plumbing and the language are commodities — assemble them. Build only the moat.**

| Piece | Build / Buy | Source if buy |
|---|---|---|
| LLM narrative + audience-adaptive draft | **Buy** | Claude / Copilot / GPT — commodity |
| Report export (PPT/PDF) | **Buy** | libraries — commodity |
| Client portal delivery | **Buy / partner** | CloudRadial pattern |
| vCIO narrative templates | Buy / reference | myITprocess, vCIOToolbox |
| Security-posture scoring | **Buy / partner** | Cynomi, N-able N-sight |
| Per-vendor connectors | Buy / partner | Rewst, Liongard, vendor APIs |
| Backup normalization | Buy (careful) | Backup Radar — but ScalePad-owned (competitor) |
| **Cross-vendor normalization → apples-to-apples** | **BUILD** | nobody sells it end-to-end |
| **Provenance / drillable traceability** | **BUILD** | the trust discipline — can't buy credibly |
| **Enter / connect-your-stack trust moment** | **BUILD** | the untested #1 risk |
| **Network-effect mapping layer** | **BUILD** | accrues; can't be bought |

**Hardest to replace — where build budget concentrates:**
1. **The cross-vendor normalization semantic layer** — makes SentinelOne + CrowdStrike + Cove + ConnectWise comparable apples-to-apples. Nobody sells it end-to-end (two absence-findings); Backup Radar proves it's buildable *and* acquire-worthy for one data type.
2. **Its network effect** — mappings that improve as more MSPs connect. A competitor copies a feature; they can't copy the accrued corpus. **The only real answer to "Derek could build it in a day"** — his build has no network.

Provenance/trust discipline is second-hardest (easy to state, hard to do credibly). **Note the overlap: the hardest-to-replace thing (normalization) is also the least-proven (#2 / Gate A). Gate A validates the moat, not just feasibility.**
