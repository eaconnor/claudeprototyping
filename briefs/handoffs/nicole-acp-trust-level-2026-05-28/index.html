What Changes Trust Level?

Trust increases: Consistent success rate >95% over 30+ days, clean escalation handling, no scope violations.

Trust decreases: Critical error (immediate rollback to L3), scope violation, failed escalation, or success rate drops below 90% over 7 days.

Value Ledger Summary

Since graduating to L4 autonomy (14 days ago):

  • 18 patch deployments executed without human confirmation
  • Estimated time saved: 4.5 hours (15 minutes per deployment)
  • Zero escalations required

At L3 (human confirms), these same tasks would have required technician review before each execution.

Tier 2 · Direction
Testing whether showing trust-score math builds confidence or creates cognitive load

What You Nailed

  • The five-component trust model maps directly to Ewan Cameron's L4 earned autonomy architecture
  • Value Ledger connection makes the business case visible: L4 = time compounding, L3 = time plateaued
  • Rollback conditions named explicitly (critical error = immediate downgrade)
  • Realistic seed data: 97% success rate over 32 executions is plausible for mature coworker

What Will Hurt You

  • No user research confirming MSPs want to see this math—may be cognitive load without benefit
  • Risk classification shows "Low" but doesn't define the taxonomy (severity? reversibility? scope?)
  • Success threshold (95% over 30 days) not sourced—engineering may have different criteria
  • False precision risk: showing 97% implies more certainty than model may have with 32-execution sample size

Product

Product does: Define risk taxonomy for trust-level calculation (severity-based? reversibility-based? scope-based?) and map to L3/L4 thresholds.
Why now: Trust level is the permission structure that determines whether Expert Licensing value compounds (L4) or plateaus (L3). [A] Layer 3 monetization depends on MSPs believing trust level accurately reflects risk. [R]
If you ship without it: Engineering implements arbitrary thresholds, MSPs see coworkers downgraded for unclear reasons, trust in the system erodes, Expert Licensing adoption stalls.
[ROI]

Business: Unknown—no data on how trust-level transparency affects Expert Licensing conversion. Need baseline graduation rates (L3→L4) to measure impact.

User: Reduces cognitive load if MSPs currently second-guess autonomy decisions; increases cognitive load if they don't. Discovery research required.

Unknown: Do MSPs want to see the math, or just the outcome? What percentage of MSPs currently override L4 recommendations by forcing manual approval?

75% Nicole (trust components, monetization link, L4 definition) / 25% Tool (taxonomy structure, rollback conditions)

Design

Design does: Run task-based usability test with 5-8 MSPs: "Your coworker's trust level just changed. Why? What would trigger a rollback?" Measure comprehension vs. time spent reviewing UI.
Why now: The brief assumes transparency builds confidence, but we have no evidence MSPs asked to see the calculation. [A] If this creates cognitive load without benefit, the UI becomes a tax on every trust-level interaction.
If you ship without it: You build a feature no one needs. MSPs ignore the breakdown, or worse, spend time trying to understand it and resent the complexity.
[ROI]

Business: Unknown—testing de-risks investment before engineering builds production-ready calculation UI. Prototype cost: ~8 hours. Production build without validation: ~80 hours.

User: Prevents shipping cognitive load disguised as transparency. If test shows MSPs only care about outcome ("safe to proceed?"), design can simplify to badge system instead of numeric breakdown.

Unknown: What mental model do MSPs currently use for autonomy decisions? Do they think in terms of "trust score" or "task safety"?

70% Nicole (testing hypothesis, cognitive load risk, L4 concept) / 30% Tool (test structure, success criteria)

Research

Research does: Discovery interviews with 8-10 MSPs (mix of new and experienced ACP users). Core question: "Walk me through how you decide whether to let this coworker execute autonomously."
Why now: The entire problem statement is assumed. [A] We have no evidence MSPs under-trust or over-trust coworkers. Ewan Cameron's experiment validated L4 as "self-evident UX" for mature MSPs [R]—which may mean they don't need the math exposed.
If you ship without it: You build based on Product's hypothesis about MSP behavior instead of observed reality. If MSPs already trust the outcome, you've added UI complexity to solve a non-problem.
[ROI]

Business: De-risks Expert Licensing roadmap. If trust-level transparency is critical to adoption, it moves up the backlog. If it's noise, Product deprioritizes and focuses on value ledger instead.

User: Ensures MSPs get the information they actually need to make autonomy decisions, not the information Product assumes they need.

Unknown: What percentage of MSPs currently at L3 feel blocked by lack of transparency vs. blocked by risk aversion? Are we solving an information problem or a confidence problem?

80% Nicole (L4 validation, self-evident UX insight, autonomy framing) / 20% Tool (interview structure)

Engineering

Engineering does: Instrument live trust-level calculation in ACP backend. Pull baseline data: What % of coworkers are currently L3 vs. L4? Average time to graduation? Rollback frequency?
Why now: The prototype uses realistic but fictional data (97% success rate over 32 executions). [A] Without real distribution data, we don't know if this UI is showing an edge case or the norm.
If you ship without it: Design tests a UI with seed data that doesn't reflect production reality. MSPs see the real UI and it feels wrong because the numbers don't match their lived experience.
[ROI]

Business: Baseline data establishes success metrics for Expert Licensing. If 80% of coworkers graduate to L4 within 60 days, that's the floor. If only 20% graduate, monetization model needs adjustment.

User: Real data informs realistic expectations. If most coworkers stay at L3 for 6 months, showing a 97% score after 45 days sets false expectation of fast graduation.

Unknown: What's the actual success rate distribution? Are most coworkers clustered at 85-90%, or is there bimodal distribution (either very high or very low)?

65% Nicole (L4 graduation concept, Expert Licensing dependency) / 35% Tool (instrumentation plan, baseline metrics)
